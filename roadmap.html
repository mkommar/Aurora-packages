03 / Prioritized roadmap

Earn the next layer.

The roadmap is ordered by leverage, not spectacle. Every stage has a dependency, a gate, and a reason it matters.

Status legend: delivered foundations · active scope · planned. This is a product roadmap, not a promise of dates.

P0
FOUNDATION / CURRENT

Make the guest trustworthy.

Close the loop around the existing BIOS/QEMU target so failures are reproducible and system state is observable.

Worktest harness, process limits, /proc visibility, package install/upgrade safety
Depends oncurrent kernel, native ABI, deterministic package artifacts
Gaterepeatable guest regression with documented pass/fail boundaries
Why it mattersWithout a trustworthy loop, every later feature is anecdote.
P1
COMPATIBILITY / NEXT

Make real software comfortable.

Expand the bounded Linux-compatible ABI where it unlocks the GCC/Bash/Make workflow without importing Linux’s entire surface.

WorkPTYs, Unix sockets, flock, broader GNU validation, Linux portability
Depends onP0 observability and stable descriptor/process semantics
Gateselected GNU workloads build and run inside the target regression suite
Why it mattersCompatibility becomes useful when developers can stay in the machine.
P2
DURABILITY / AFTER P1

Make state survive.

Turn storage and service behavior from a documented capability into something dependable across restart and recovery.

Workstorage validation, service restart, swap, stronger package lifecycle and recovery
Depends onstable process controls, filesystem semantics, and failure telemetry
Gatepower-cycle/restart scenarios preserve or safely recover declared state
Why it mattersSystems work is about the second boot, not only the first demo.
P3
HARDWARE / EXPANSION

Leave the emulator carefully.

Broaden the hardware contract only after the virtual contract is measurable.

WorkUEFI path if still required, device coverage, IPv6, more storage/network adapters
Depends onP2 durability and a clear hardware support matrix
Gatehardware targets have automated smoke tests and recovery stories
Why it mattersHardware breadth multiplies every debugging path; earn it with evidence.
P4
ECOSYSTEM / LONGER HORIZON

Make the small system welcoming.

Build contributor and application ergonomics around the boundaries Aurora has proven.

Workdesktop shell, signed package distribution, richer tooling and docs
Depends onall prior gates; especially package trust and hardware confidence
Gatenew builders can reproduce, extend, and explain a system install
Why it mattersAn understandable OS becomes valuable when more people can shape it.
